# Workflow Philosophy

## AI is a collaborator, not autonomous production

AI should assist:
- exploration
- implementation
- iteration
- debugging
- refactoring

But humans must still control:
- architecture
- interaction philosophy
- product identity
- final UX judgment
- production direction

---

## Preserve continuity over speed

Fast AI iteration is dangerous when:
- interaction systems become complex
- animation systems become interconnected
- state architecture becomes fragile
- UI personality becomes highly customized

Protect continuity before optimizing speed.

---

## Stable systems are more valuable than rapid rewrites

Large AI-generated rewrites often:
- damage interaction consistency
- break animation continuity
- introduce hidden regressions
- normalize unique UX patterns

Prefer controlled iteration.

# Cursor Workflow Skills

## Use Ask mode before Agent mode

Use Ask mode first for:
- architecture changes
- animation rewrites
- layout systems
- fullscreen behavior
- interaction refactors
- state synchronization

Reason through changes before allowing AI execution.

---

## Agent mode should execute scoped tasks

Prefer:
- small isolated changes
- clearly bounded tasks
- incremental iteration
- reversible edits

Avoid:
- massive one-shot refactors
- broad system rewrites
- uncontrolled file modifications

---

## Preserve working states frequently

Before changing:
- animation systems
- rendering logic
- layout architecture
- fullscreen behavior
- interaction timing

Always create checkpoints.

Working systems are expensive to rebuild.

---

# Git Workflow Skills

## Commit before experimentation

Before:
- visual experiments
- animation tuning
- interaction rewrites
- AI-generated refactors

Create git commits first.

This enables:
- rapid rollback
- experimentation freedom
- safer iteration

---

## Use tags before dangerous rewrites

Before changing:
- desktop window systems
- rendering pipelines
- database structure
- storage architecture
- fullscreen systems

Create git tags.

Tags provide stable recovery anchors.

---

## Small commits preserve project memory

Prefer:
- focused commits
- descriptive commit messages
- incremental progress tracking

Avoid large unclear commits.

Project history is part of production memory.

# AI Behavior Skills

## AI tends to normalize interfaces

AI models naturally drift toward:
- generic SaaS layouts
- standard web UI patterns
- simplified interaction systems
- over-optimized interfaces

Protect:
- cinematic pacing
- asymmetrical layouts
- immersive hierarchy
- interaction personality
- custom motion language

---

## AI tends to over-refactor

AI frequently attempts to:
- simplify architecture aggressively
- merge unrelated systems
- remove intentional complexity
- rewrite stable code unnecessarily

Not all complexity is bad.

Some complexity preserves:
- UX quality
- animation stability
- interaction continuity
- product identity

---

## AI can damage interaction feel invisibly

AI-generated code may appear technically correct while damaging:
- pacing
- motion feel
- spacing rhythm
- interaction weight
- cinematic continuity

Always visually validate interaction changes.

---

# Production Safety Skills

## Runtime behavior matters more than generated code

Generated code is not the final product.

Always validate:
- runtime behavior
- animation smoothness
- browser consistency
- interaction feel
- fullscreen transitions
- resize behavior

Production behavior is the real source of truth.

---

## Browser previews are not always reliable

Embedded preview environments may differ from:
- standalone browsers
- production deployments
- iframe environments
- real device behavior

Always test real runtime environments.

---

## Build and deploy frequently

Local environments may hide:
- rendering differences
- deployment issues
- production timing issues
- browser inconsistencies

Frequent deployment reduces integration surprises.

---

# Long-Term AI Collaboration Skills

## Skills are reusable production memory

Each project generates:
- workflow lessons
- debugging knowledge
- interaction philosophy
- animation knowledge
- AI behavior constraints

Preserve these lessons.

Future projects should inherit past production experience.

---

The long-term goal is not:
- generating code faster

The real goal is:
- preserving product personality
- preserving interaction philosophy
- maintaining cinematic consistency
- building reusable AI collaboration systems

AI-native production is fundamentally about continuity.
